# ДОМ·ЛЕС

Конфигуратор деревянных домов и **кровельная лаборатория** — расчёт нагрузок, ведомость распила, карта раскроя и смета по крыше. Всё считается в браузере, бэкенда нет.

Стек: **Vite 5 + three.js 0.169**, чистый ES-модульный JavaScript без фреймворков и без TypeScript. Node 18+ (проверено на 20).

---

## 1. Что лежит в репозитории

В репо **два самостоятельных продукта**. Они пока не связаны между собой.

| | Что это | Точка входа | Состояние |
|---|---|---|---|
| **Дом·Лес** | 3D-конфигуратор дома: планировка, прогулка от первого лица, лестницы, веранды, фундамент, смета, экспорт проекта в JSON | `index.html` → `src/main.js` | Рабочий. Крыша в нём — **визуальная** (`src/roof.js`), без инженерии |
| **Кровельная лаборатория** | Инженерный движок крыши: геометрия, нагрузки, несущая способность, ведомость деталей с марками, раскрой по заготовкам, смета, 3D-сцена со сборкой по этапам | `roof-lab.html` → `src/roof/lab.js` | Основной фокус разработки. Покрыт тестами |

**Зачем лаборатория:** инженер получает **карту раскроя** и **ориентировочную цену**, которую можно назвать клиенту. Не картинка, а документ.

Мост между продуктами — `src/roof/roof-context.js` (`roofFromHouse`) — написан, но **нигде не вызывается**. Интеграция запланирована после того, как крыша будет доведена.

## 4. Архитектура: поток данных

```
параметры (ROOF_DEFAULTS + правки пользователя)
        │
        ▼
computeRoofModel(params) ──────────► model      геометрия, объёмы, нагрузки-заготовки
        │
        ▼
computeRoofStructure(params, model) ► structure  проверки несущей способности
        │
        ▼
computeRoofPieces(params, model) ──► pieces     ведомость деталей с марками
        │
        ▼
planLongMembers(model, params, pieces) ► plan    прогоны/стойки/стыки + свои детали
        │
        ▼
nestRoofPieces(pieces, params) ────► nesting    раскрой по заготовкам, отход
        │
        ├──► roofBOM + roofPrice ──► lines, estimate
        └──► roofChecks ──────────► checks
        │
        ▼
createRoofStage.rebuild(model, params) + buildHardware(model, params, structure)
```

**Правила, которые нельзя нарушать:**

1. **Ядро чистое.** `roof-model`, `roof-structure`, `roof-mansard`, `roof-pieces`, `roof-nesting`, `roof-long`, `roof-bom`, `roof-checks` не импортируют `three` и не трогают DOM. Их можно гонять в Node.
2. **three только в `roof-render.js` и `roof-hardware.js`.** На границе векторы ядра принудительно приводятся к `THREE.Vector3` через `T3()` — иначе падают методы вроде `.negate()`.
3. **Порядок расчёта задан в `roof-controller.js`.** План опор считается внутри вывода, чтобы его детали попали в распил и смету наравне с остальными.
4. **Один источник истины на величину.** Мёртвая нагрузка, толщина пирога, ширина прогона — считаются один раз и передаются дальше, а не пересчитываются в двух местах.

## 5. Система координат ската

Самое важное для тех, кто правит геометрию. У каждого ската `f` есть локальный базис `f.basis = eulerBasis(f.rot)` и точка отсчёта `f.pos`.

| Ось | Направление |
|---|---|
| **X** | вниз по скату, от конька (или от точки перелома для нижнего ската мансарды) |
| **Y** | наружу, перпендикулярно скату. **Подошва стропилы — Y = 0, верхняя грань — Y = rd** |
| **Z** | вдоль конька |

Перевод в мир: `L2W(f, X, Y, Z) = f.pos + basis.X·X + basis.Y·Y + basis.Z·Z`.

### Профиль стропилы

```js
[[xa, 0], ...notch, [xb, 0], [xb - D*ta, D], [xaTop, D]]
```

Торцы резаны **вертикально** (plumb cut): наклон кромки `dX/dY = −tan α`. Из-за этого **верхняя грань короче и сдвинута к коньку на `rd·tan α`** относительно нижней. Отсюда следствия:

- `f.xPie0 = −rd·tan α` — начало пирога. Точка `(xPie0, rd)` лежит ровно на оси конька / линии перелома. Если класть пирог от нуля, вся кровля «съезжает» вниз по скату на `rd·sin α`.
- `f.xTopLimit` — предел для верхнего угла головы стропилы, чтобы он не вылез за кровлю.
- `f.headSeat` — площадка опирания головы нижнего ската на прогон перелома.
- `msMiter` — смещение, при котором верхние грани пирогов двух скатов сходятся в одну линию на изломе.

### Аналитические поверхности

- `roofUnder(x, z)` — низ кровли (подошва стропил).
- `roofTop(x, z)` — верх покрытия: `roofUnder + coverTop / cos α`. Вне габарита возвращает `−Infinity`.

## 8. Пирог кровли

Толщины констант в `roof-model.js`:

| Слой | Переменная | Толщина |
|---|---|---|
| Мембрана | `memT` | 5 мм |
| Контробрешётка (вентзазор) | `cntH` | 50 мм |
| Обрешётка | `batT` | 25 мм |
| Сплошной настил | `deckT` | 12 мм |
| Покрытие | `covT` | 28 мм |

Уровни по Y от подошвы стропилы:

```
yMem     = rd
yCnt     = rd + memT
yBat     = yCnt + cntH
covY     = yBat + (solid ? deckT : batT)
coverTop = covY + covT
```

Пирог лежит на **верхней грани** стропилы, начало по X — `xPie0`, конец — `rlPie` (обрезан по лобовой доске).

## 9. Нагрузки и несущая способность

Справочники в `roof-params.js`:

- `SNOW` I…VIII = 0.8…5.6 кПа (СП 20), `WIND` I…VII = 0.23…0.85 кПа
- `GRADE` 1/2/3: `Ri` (изгиб), `Rt` (растяжение), `Rsm` (смятие), `E` (модуль), МПа
- `RHO = 500` кг/м³ — плотность сосны
- `GL` — клеёная балка GL24h

Функции в `roof-mansard.js`:

| Функция | Что делает |
|---|---|
| `snowMu(deg)` | коэффициент снегового покрова: 1 при ≤30°, 0 при ≥60°, линейно между |
| `slopeLineLoad(deadKN, caS, deg, Sg, step)` | погонная нагрузка на стропилу с коэффициентами 1.1 / 1.4 |
| `checkRafterSection(sect, runH, caS, qPair, G, seatWmm, meta)` | возвращает `utilR` (изгиб), `utilD` (прогиб), `utilSm` (смятие), `ok` |
| `pickRafterSection(cases, G, seatWmm, minSect)` | минимальное проходящее сечение из `RAFTER_SECTIONS` |

Прогиб считается по нормальной составляющей: `q⊥ = q·cos²α`, пролёт по скату `Ls = runH / cos α`, предел `Ls/200`.

`computeRoofStructure` считает мёртвую нагрузку **из объёмов модели** (одна формула на проект) и возвращает `utilR/utilD/utilSm/utilB/utilT`, `boltLayout`, `rafterCases`, `govTag`.

## 10. Мансарда

Четыре схемы (`MANSARD_SCHEMES`):

| Схема | Идея |
|---|---|
| `broken` | ломаный скат: низ 45…75°, верх 15…40°. Ригель в переломе — потолок комнаты |
| `tie` | висячие стропила с затяжкой по полу, бабка и подкосы над потолком |
| `ridge` | клеёный коньковый прогон на фронтонах, решётки над потолком нет |
| `truss` | заводская ферма с проёмом под комнату; хорды считает завод |

### Как работает ломаный скат

Это **два замкнутых треугольника**:

- верхний: две верхние стропилы + ригель на уровне перелома → распор замыкает ригель;
- нижний: две нижние стропилы + балки перекрытия → распор замыкает пол.

Наружу из верхнего треугольника выходит только **вертикальная реакция** в углах перелома. Её принимает **прогон перелома** (`BP_W = 150`, `BP_D = 250 мм`) — обвязка по стойкам боковой стены комнаты (`roomStud`). Колонн внутри комнаты нет.

### Поска́тные сечения

Нижний крутой скат пилятся из **своего, меньшего** сечения: при 62° снег `μ = 0`, пролёт короткий. Глубина ограничена условием смыкания излома:

```
rd_низ / cos α_низ  ≤  rd_верх / cos α_верх
```

Результат — `MS.sectLower` / `MS.checksLower`. При `mansardAutoSection = 0` ничего не меняется: сечение задал инженер.

### Поля `MS`

`roomH`, `ceilHalf`, `breakX`, `breakY`, `ridgeY`, `lowA/highA`, `lowRL/highRL`, `kneeTop`, `eaveY`, `sect`, `sectLower`, `checks`, `cases`, `tieForce`, `bottomTieForce`, `tieN`, `tieUtil`, `parts`, `rejectedParts`, `hasUpper`, `upperStep`, `tieLift`, `warnings`, `notes`.

`parts[]` — члены решётки: `{t:'box'|'brace', s|a/b, p, zs, mat, tag, st, mk:[группа, длина]}`. > **Новую группу нельзя завести «на месте».** Нет записи в `PIECE_GROUPS` — деталь молча выпадает из ведомости и раскроя.

### Раскрой (`nestRoofPieces`)

Группировка по сечению → сортировка по длине ↓ → best-fit в заготовки `stock` с учётом пропила `kerf`. Детали длиннее заготовки уходят в `over` (заказные) и **тоже учитываются в отходе**. Возвращает `bins`, `over`, `boards`, `waste`, `vol`, `usable`.

### Смета

`roofBOM` собирает строки (материалы, работа, распил), `plan.bom` добавляет опорные детали, `roofPrice` считает итог. Ставки — `RATES`, редактируются на вкладке «Цены», хранятся в localStorage (`loadRates` / `saveRates` / `resetRates`).

### Выгрузки

`cutCSV` — ведомость, `nestCSV` — раскрой, `assemblyCSV` — сборка по этапам, `packageJSON` — полный пакет (`project, date, params, geometry, structure, checks, pieces, nesting, assembly, rates, estimate`).

## 12. Сборка и слои

**14 этапов** (`ROOF_STAGES`, индексы 0…13): площадка → мауэрлат → балки → лежень → стойки и прогон → накосные → стропилы с ригелями → подкосы → полуноги → свесы → мембрана и контробрешётка → обрешётка → покрытие → конёк и водосток.

**17 слоёв** (`ROOF_LAYERS`): у каждого `id`, имя, цвет, `s` (смещение при разлёте), `st` (этап появления). Слайдер этапа скрывает всё, что появляется позже.

### Соглашения `userData` в сцене

| Ключ | Смысл |
|---|---|
| `st` | этап сборки |
| `mk` | марка детали (должна быть в ведомости) |
| `hw` | это крепёж |
| `msPart` | тег члена мансарды |
| `msAxis` | осевые точки детали для страховки контура |
| `vertSupport` | вертикальная опора (проверяется на «висит в воздухе») |
| `culled` | снят страховкой контура |
| `faceTag` | принадлежность скату (`upper`/`lower`/`main`) |
| `joint` | ключ стыка `индекс:X` |
| `ridgeBeam`, `sect` | коньковый прогон и его сечение |
| `mansardTie`, `tieTop` | ригель мансарды и уровень верха |

Записи вида `me.userData[q.tag] = true` — **динамические**. Статические анализаторы их не видят.

### Страховка контура

После сборки каждый член мансарды проверяется: его **осевые точки** (`msAxis`) не должны подниматься выше `roofAtW(x)` более чем на 160 мм; габарит по Z — `L/2 + 0.35`. Проверяются именно осевые точки, а не bbox: у раскоса верхняя точка стоит у малого X, и центр коробки врёт.

## 13. Тесты

### Аудит ядра и сцены — `roof-audit.html`

33 конфигурации (`AUDIT_MATRIX`), ~2270 проверок. Домены:

| Префикс | Домен |
|---|---|
| `X` | целостность (форма, число скатов, исключения) |

| `N` | мансарда |
| `C` | ведомость и раскрой |

Три статуса падения:
- **БАГ** — сломано, надо чинить;
- **НОРМА** (`expected`) — запланированное нарушение норм слабым сечением, так и задумано (7 штук);
- **ПРОПУСК** — проверка неприменима (например, ферма: хорды считает завод).

### UI-тесты — `roof-ui-test.html`

52 сценария в 10 группах: Запуск, Мансарда, Схемы, Геометрия, Вид, Сборка, Вкладки, Экспорт, Отзывчивость, Устойчивость. Драйвер работает через хук `window.__roofTest` в `lab.js` (`ready`, `builds`, `params`, `summary`, `errors`, …).

### Формат отчёта

Компактный JSON, **только падения**. Ожидаемые нормы и пропуски — одной цифрой в `totals`. Параметры — только отличия от дефолта.

```json
{"t":"2026-11-26T08:12:37.536Z","mode":"core+scene",
 "totals":{"configs":33,"checks":2271,"bugs":0,"norms":7,"skipped":3},
 "fails":[]}
```

Если что-то упало:

```json
{"fails":[{"cfg":"Мансарда · ферма 10×12","form":"mansard",
  "p":{"mansard":1,"mansardScheme":"truss"},"checks":88,"sect":"50x200",
  "bugs":[{"id":"R22","n":"Ничего не снято страховкой контура","d":"trussWeb"}]}]}
```

> **Правило:** отчёт снимается **с того же коммита**, на котором прогонялись тесты. Иначе чинятся призраки. После правок перезапускай `npm run dev` и делай жёсткую перезагрузку — Vite может отдавать закэшированный модуль.

### Статический аудит — `audit-project.mjs`

Полезен для карты импортов, но **даёт ложные срабатывания**: не видит динамические записи `userData[tag]` и путает одноимённые поля у разных объектов. Его «ошибки» нужно перепроверять чтением кода.

## 14. Грабли, на которые уже наступали

1. **Дублирование формул.** Мёртвая нагрузка считалась в модели и в расчёте по-разному → расхождение вдвое. Теперь одна формула.
2. **Функция с двумя аргументами, вызванная с одним.** `deadKgOf(rd)` вместо `deadKgOf(rt, rd)` → ширина подставлялась как высота.
3. **Присвоение после `break` в цикле.** Итоги подбора не выполнялись на сходящейся итерации.
4. **Присвоение до инициализации.** `out.tieLift` читал `out.sect`, которого ещё нет → `Cannot read properties of undefined`.
5. **Один якорь в двух патчах.** Строка вставлена дважды — ранняя падает.
6. **Смешение систем отсчёта.** `tx` от перелома, `ty` от конька → конец раскоса висел в 240 мм под стропилой.
7. **Нахлёст в плоскости вместо нахлёста сбоку.** Деталь начинала проходить сквозь другие члены.
8. **bbox вместо осевых точек** в страховке контура → исправные раскосы снимались.

Общее правило: **сначала проверь, в какой системе координат и от какой грани считается величина.** Почти все визуальные дефекты были из-за этого, а тесты их не ловили.
